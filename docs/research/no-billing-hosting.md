# Hosting without a payment card or enabled billing

Checked: 2026-10-08. Scope: the existing Python FastAPI application, local EmbeddingGemma ONNX q4 queries, and durable human edits/reviews. This is research, not an account eligibility check or deployment.

## Finding

No examined general-purpose free cloud tier is a verified direct fit for all three requirements: the existing application, enough RAM for local semantic queries, and durable SQLite with no payment method or paid subscription. This does not establish that no such provider exists. PythonAnywhere is the closest candidate, but its disk limit and experimental ASGI offering need an actual compatibility check. A public demonstration can preserve the canonical app by running it on the existing PC behind a temporary Cloudflare Quick Tunnel; that is PC hosting, not independent cloud compute.

The project's historical q4 measurement is **587 MB peak process RSS**, including Python/runtime, not a measurement of the complete web application or just the model weights. Therefore 512 MB hosts already fail the measured embedding process budget. See [the local spike](local-embeddings-spike.md). The application uses pinned native `onnxruntime`, `tokenizers`, NumPy and scikit-learn dependencies in `pyproject.toml`; its runtime must support these, not merely the Python language. Human edits/reviews use mutable SQLite, while G10's frozen demonstration intentionally loads no model: [G10 contract](../g10-offline.md).

PythonAnywhere's current free signup form should be checked before creating an account; this report did not verify actual signup or claim card-free ASGI entitlement. Its older official [free-account announcement](https://blog.pythonanywhere.com/206/) describes persistent home storage, but its old task/expiry details are superseded by the current free features page. Console CPU allowance is not automatically a per-web-request CPU budget. Locally, processed data, outputs and backend static assets total about **62 MiB** (read-only file measurement); the q4 model is documented at about 218 MB. Dependencies, caches, database growth and installation overhead still need disk accounting, so these figures do not prove a 512 MiB install fits.

Cloud Run is outside the strict requirement: it can allocate 2 GiB and scale to zero, but its free allowances require an active billing account and paid-account overages are charged. [Billing requirement](https://docs.cloud.google.com/free/docs/free-cloud-features), [memory configurations](https://docs.cloud.google.com/run/docs/configuring/services/memory-limits).

## Concrete route preserving the canonical application

Use the existing PC for a supervised public demonstration: keep the real FastAPI app, q4 query model, verified corpus vectors, BM25 fusion and SQLite on local storage. Do not start `offline-demo serve` and imply it has free semantic query execution; G10 is intentionally frozen. First verify the normal app's semantic mode and that a review survives restart, with its database at an explicit persistent path. This is a proposed validation, not a completed check.

Cloudflare [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) creates a temporary HTTPS URL for a local HTTP server without a Cloudflare account or domain. The URL dies when `cloudflared` stops, has no uptime guarantee, supports up to 200 in-flight requests, and does not support SSE. Current docs describe optional email/PIN access with `--allowed-mail`; the installed client version must support it before relying on it. Because Python/model/database stay on the PC, this route does not subject them to Workers' 128 MB runtime limit. That is an architecture inference, not a cloud deployment measurement. The PC, app, tunnel and internet connection must stay active; existing power/connectivity costs remain.

For the next implementation, add a reproducible local launch/check workflow with an explicit data path and a separately invoked tunnel command. Check current app authentication and write endpoints before public exposure; token/auth behavior must be concrete rather than assumed. Do not launch an unrestricted public tunnel merely to obtain a URL. Preserve the offline G10 artifact and the canonical app, and keep q4 until the approved human-reviewed q4/fp32/BM25 comparison.

For independent cloud hosting, verify a connected PythonAnywhere free account and ASGI availability, then measure a clean install using the supported system site packages and model cache without altering model revisions. If that fails, report the exact disk/runtime restriction; do not enable billing or change retrieval/persistence silently. Browser-side ONNX with free static hosting and browser IndexedDB is a possible separate architecture, but local browser reviews are not shared durable server reviews and require an explicit product decision.

## Account and evidence gaps

No connected account, token, GitHub deployment authorization, free-plan eligibility, model license acceptance, or provider signup has been verified by this research. No website was created, no billing enabled, and no account created. A no-account Quick Tunnel requires only the client and a running local service, but remains a temporary demo. The research establishes provider constraints; it does not claim a deployed public URL, restart persistence, install size, or complete free-cloud feasibility.
